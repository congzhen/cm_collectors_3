# 已有图片的批量导入压力验证

## 测试方法

2026-11-14，在 Windows 上使用隔离临时目录、SQLite 和真实导入处理器运行两批各 320 条资源。每条资源拥有独立路径和同名本地 JPEG，图片为 6000×4000（2400 万像素），压缩大小 710,918 字节。第一批保留原图，第二批裁剪为 400×600。

视频使用占位文件，关闭导入清晰度探测并暂停后台视频信息采集；自动生成封面开关保持开启，以验证已有匹配图片时正常使用本地封面。测试真实执行图片读取、裁剪、封面落盘、资源与分集入库、备份计数和自动备份 ZIP 生成，不启动 HTTP 服务，不读取业务数据库。

以 10 毫秒间隔采样 Go 堆、Windows 工作集和私有内存。正常导入期间不强制 GC，只在批次前后执行 GC 以比较存活堆。内存峰值包含自动备份阶段；采样可能错过短暂峰值。两批在同一进程依次运行。

## 已验证结果

| 项目 | 保留原图，320 条 | 裁剪，320 条 |
| --- | --- | --- |
| 导入及封面尺寸核对耗时 | 2.445 秒 | 49.905 秒 |
| 批次前 → 导入后 GC 存活堆 | 106.0 → 106.0 MiB | 107.1 → 106.3 MiB |
| 累计内存分配量（不是峰值） | 2214.0 MiB | 11889.0 MiB |
| 采样 Go 堆峰值（含备份） | 215.2 MiB | 290.1 MiB |
| 采样进程工作集峰值（含备份） | 144.2 MiB | 221.5 MiB |
| 采样进程私有内存峰值（含备份） | 275.4 MiB | 351.8 MiB |
| 导入结束至自动备份完成 | 2 分 11 秒 | 2 分 13 秒 |
| 导入结果 | 320 成功，0 警告，0 失败 | 320 成功，0 警告，0 失败 |

每 80 条核对实际入库数及待备份变更数，两者均为 80、160、240、320。裁剪批次各检查点堆内存约 180 MiB，没有随条数累积的趋势。逐条读取保存后的 JPEG 头验证封面尺寸。

自动备份阈值为 100。导入中主动调用实际自动备份入口检查门禁，并保留真实队列定时器；批次结束后立即再次调用，确认 30 秒空闲窗口未被绕过。原图批次在结束约 2 分 11 秒后完成自动备份，ZIP 包含 320 张封面，待备份变更计数归零。此前 100 秒等待上限不足，调整测试等待上限为 5 分钟后继续核验；没有修改产品的备份延迟或限速。

前端独立组件测试以 320 个可控异步响应逐条推进，验证每个在途请求不提前计数，最终为 320/320、成功 320；同时运行混合结果、取消、断连、租约过期、重试隔离等共 12 项测试，全部通过。前端类型检查通过。

裁剪批次完成后自动备份 ZIP 包含两批共 640 张封面，待备份计数归零。两批业务子测试均 PASS。该轮整个 Go 测试最初因 Windows 日志句柄占用导致临时目录清理失败；测试配置已将日志改到 `NUL`，并用 `-run '^TestImportStressLocalPosters$/^$'` 单独执行父测试初始化和清理验证通过（不重复执行两个批量子测试）。本轮只增加测试及记录，未改业务逻辑。

## 复现命令与边界

服务端目录单独运行（该测试使用进程全局配置，不与其他集成场景混跑）：

```powershell
go test -tags=importstress -vet=off ./processors -run '^TestImportStressLocalPosters$' -v -count=1 -timeout=15m
```

主前端目录：

```powershell
yarn.cmd test:unit --run src/components/importResource/__tests__ --pool=threads --maxWorkers=1 --minWorkers=1 --reporter=verbose
yarn.cmd type-check
```

该结果不是浏览器到 HTTP 接口的端到端压测，也不包含真实视频探测、NFO 演员图片、网络磁盘或多库并行。没有测量浏览器内存；不能据此排除用户原始目录及其他设置下的崩溃。
