# 视频元数据采集与历史补齐设计

## 背景

当前系统已经通过 FFprobe 获取视频格式信息，但自动持久化只保存分集时长：

- `resourcesDramaSeries.durationSeconds`
- `resourcesDramaSeries.durationProbeStatus`
- `resourcesDramaSeries.durationProbeTime`

播放、导入、视频指纹、播放诊断和 AI 自动标签等流程还会临时读取宽高、码率、编码和封装格式，
这些结果没有进入统一的数据模型。现有时长采集由文件库的 `showVideoDuration` 展示开关触发，
只处理当前列表页、新建和修改后的资源，使用单 worker 内存队列串行执行。

扩展视频信息后，需要同时解决：

- 新视频一次采集完整元数据。
- 旧数据库中已有时长但没有其他元数据的数据兼容。
- 本地磁盘、NAS、移动硬盘采用不同补齐策略。
- 列表、详情、播放、手动补齐、空闲补齐和计划任务不会重复探测同一分集。
- 长时间补齐任务可以暂停、恢复，并在服务重启后继续。
- 计划任务第一版支持一个、多个或全部文件库。

## 目标

- 使用一次 FFprobe 保存时长、宽高、帧率、编码等稳定的核心元数据。
- 保留已有 `durationSeconds`，升级时不清空、不阻塞启动、不立即扫描历史文件。
- 将现有视频时长采集整合到统一的视频元数据采集器，不再维护独立时长队列。
- 支持以下自动触发方式，并允许用户分别配置：
  - 新增分集、路径变化或文件变化。
  - 打开资源详情或播放。
  - 浏览资源列表页。
  - 软件空闲时补齐历史数据。
- 历史列表补齐和空闲补齐默认关闭，避免升级后主动遍历 NAS。
- 提供独立补齐管理窗口，支持一个、多个或全部文件库。
- 增加视频元数据计划任务，支持多库和全部库范围。
- 所有入口共用一个调度器，以分集 ID 去重，默认只运行一个元数据 FFprobe worker。
- 支持元数据版本升级、文件变化失效、失败退避和中断恢复。
- 支持详情展示以及按分辨率、视频编码筛选。

## 非目标

- 第一版不保存 FFprobe 的全部原始 JSON。
- 第一版不建立完整的多视频流、音轨和字幕轨数据库。
- 第一版只保存主视频流和主音频流摘要。
- 第一版不计算完整文件哈希；文件变化使用路径、大小和修改时间判断。
- 不自动覆盖资源表中用户、NFO 或刮削结果设置的 `definition`。
- 不把视频元数据调度器扩展成所有 FFmpeg、视频指纹、截图和转码任务的全局资源调度器。
- 不在数据库迁移、服务启动或恢复旧备份时同步执行 FFprobe。

## 已确认的产品决策

### 默认触发策略

| 触发方式 | 默认值 | 说明 |
| --- | --- | --- |
| 新增、路径变化或文件变化 | 开启 | 保证新数据逐步完整 |
| 打开详情或播放 | 开启 | 优先补齐用户正在使用的数据 |
| 浏览列表页补齐历史数据 | 关闭 | 避免翻页时连续访问 NAS |
| 空闲时补齐历史数据 | 关闭 | 用户明确开启并选择范围后才运行 |
| 手动补齐 | 用户触发 | 不受自动补齐开关限制 |
| 计划任务补齐 | 用户创建 | 不受空闲补齐开关限制 |

“历史自动补齐默认关闭”不等于关闭新视频采集。每个触发方式可以在高级设置中独立修改，
普通用户界面可以提供均衡、按需、完整补齐、关闭自动采集等预设。

### 补齐范围

手动补齐、空闲补齐和计划任务均支持：

- 单个文件库。
- 选择多个文件库。
- 全部文件库。

`all` 表示执行时动态查询全部现存文件库，不保存创建任务时的静态快照，因此以后新增的文件库
也会自动进入任务范围。`selected` 保存明确的文件库 ID 集合。

三种范围彼此独立：

- 手动补齐范围只影响本次任务。
- 空闲补齐范围保存在视频元数据系统设置中。
- 计划任务范围保存在对应计划任务中。

### 并发和重复触发

任务唯一键使用 `dramaSeriesId`，不能使用资源 ID。一个资源可能包含多个分集，只能跳过正在处理
的具体分集，不能阻止同一资源的其他分集进入队列。

- 同一分集正在执行：新触发跳过，不算失败。
- 同一分集已在相同或更高优先级队列：新触发跳过。
- 同一分集在低优先级队列，随后被详情、播放或手动任务触发：提升优先级，不增加第二个任务。
- 默认只有一个视频元数据 FFprobe worker。

## 总体架构

```text
新增/文件变化 ──────── 高优先级 ─┐
详情/播放 ──────────── 高优先级 ─┤
手动补齐 ───────────── 高优先级 ─┤
列表页 ─────────────── 中优先级 ─┼─> VideoMetadataCoordinator
计划任务 ───────────── 中优先级 ─┤       │
空闲历史补齐 ───────── 低优先级 ─┘       ├─ 分集 ID 去重/优先级提升
                                         ├─ 单 worker 领取
                                         ├─ FFprobe 一次读取
                                         └─ 事务写入时长和完整元数据
```

所有入口只能向 `VideoMetadataCoordinator` 提交分集或扫描范围，不能自行执行 FFprobe。

## 数据设计

### 保留 `resourcesDramaSeries`

继续保留：

- `durationSeconds`
- `durationProbeStatus`
- `durationProbeTime`

`durationSeconds` 仍是列表显示和现有接口的兼容字段。第一版统一探测成功时继续同步更新三个字段，
但新的触发、状态和重试逻辑以视频元数据表为准。待旧逻辑完全移除后，再决定是否停止使用旧状态
字段；首次升级不删除字段。

### 新增 `resourcesVideoMetadata`

视频元数据与分集是一对零或一关系。不存在记录表示从未进行完整元数据采集。

建议字段：

| 字段 | 类型建议 | 说明 |
| --- | --- | --- |
| `dramaSeriesId` | `char(20)` | 主键或唯一索引，关联分集 |
| `metadataVersion` | `int` | 解析规则版本 |
| `probeStatus` | `varchar(20)` | `processing/success/failed/stale` |
| `probeTime` | `datetime` | 最近一次完成探测时间 |
| `nextRetryTime` | `datetime` | 失败后的下次允许重试时间 |
| `retryCount` | `int` | 连续失败次数 |
| `errorCode` | `varchar(50)` | 稳定错误分类 |
| `errorMessage` | `text` | 最近一次错误摘要 |
| `fileSize` | `bigint` | 采集时文件字节数 |
| `fileModifiedTime` | `bigint` | 采集时文件修改时间戳 |
| `width` | `int` | 主视频流编码宽度 |
| `height` | `int` | 主视频流编码高度 |
| `frameRate` | `real` | 用于显示、排序和筛选的数值帧率 |
| `frameRateRaw` | `varchar(30)` | 原始有理数，例如 `24000/1001` |
| `videoCodec` | `varchar(50)` | 例如 `h264/hevc/av1` |
| `videoProfile` | `varchar(100)` | 编码 profile |
| `pixelFormat` | `varchar(50)` | 例如 `yuv420p` |
| `bitDepth` | `int` | 8-bit、10-bit 等 |
| `videoBitRate` | `bigint` | 主视频流码率，单位 bps |
| `containerFormat` | `varchar(100)` | FFprobe 返回的封装格式 |
| `audioCodec` | `varchar(50)` | 主音频流编码 |
| `audioChannels` | `int` | 主音频流声道数 |
| `audioSampleRate` | `int` | 主音频流采样率 |

第一版不在新表重复保存时长，避免两个时长来源不一致。需要毫秒精度时再单独设计精确时长字段。

建议索引：

- `dramaSeriesId` 唯一索引。
- `probeStatus` 普通索引。
- `metadataVersion` 普通索引。
- 确定提供筛选后，为 `height`、`videoCodec` 增加索引。

删除分集或文件库时，必须同步物理删除对应元数据记录。

### 主流选择

主视频流选择顺序：

1. 只考虑 `codec_type=video`。
2. 排除 `disposition.attached_pic=1` 的封面图流。
3. 优先 `disposition.default=1` 的视频流。
4. 没有默认流时选择有效像素面积最大的流。
5. 面积相同时保持 FFprobe 原始流顺序。

主音频流优先选择 `disposition.default=1`，否则使用第一个有效音频流。

需要在 `VideoFormatInfo.Streams` 中补充：

- `avg_frame_rate`
- `r_frame_rate`
- `disposition.default`
- `disposition.attached_pic`
- 计算位深所需字段

显示帧率优先使用有效的 `avg_frame_rate`，回退到 `r_frame_rate`。原始有理数保存在
`frameRateRaw`，数值结果保存在 `frameRate`。

## 设置设计

建议新增数据库持久化的视频元数据设置，而不是把多库 ID 拼进文件库配置 JSON。

### `videoMetadataSetting`

单例设置建议包含：

- `collectOnNewOrChanged`，默认 `true`。
- `collectOnDetailOrPlay`，默认 `true`。
- `collectOnList`，默认 `false`。
- `idleBackfillEnabled`，默认 `false`。
- `idleScopeMode`：`selected/all`。
- `idleWaitMinutes`，默认 5。
- `probeIntervalMilliseconds`，默认 1500。
- `idleBatchSize`，默认 20。
- `paused`。

### `videoMetadataSettingFilesBases`

在 `idleScopeMode=selected` 时保存空闲补齐选中的文件库。一个文件库只允许一条关联记录。

删除文件库时同步清理关联；如果 `selected` 范围已经为空，空闲补齐保持关闭并在设置页提示。

`showVideoDuration` 只控制前端是否显示时长，不再决定是否允许采集元数据。

## 统一调度器

### 优先级

| 优先级 | 来源 |
| --- | --- |
| 高 | 新增、文件变化、详情、播放、手动补齐 |
| 中 | 当前列表页、计划任务 |
| 低 | 空闲历史补齐 |

手动任务默认高优先级，但仍使用单 worker，不会和播放、列表或计划任务同时探测同一分集。

### 内存去重

调度器维护：

- `queued[dramaSeriesId] -> priority`
- `running[dramaSeriesId]`
- 高、中、低三个逻辑队列

提交任务时在同一个互斥区完成检查、插入或优先级提升。worker 完成数据库写入后才释放
`running`。调用入口不得在队列外进行“先检查后执行”，避免竞态。

### 数据库领取

内存队列用于当前进程的低延迟去重，数据库状态用于重启恢复：

- worker 真正开始前，将元数据记录原子更新或插入为 `processing`。
- 如果记录已经是本进程正在处理的分集，直接跳过重复领取。
- 服务异常退出遗留的 `processing` 记录不能永久阻塞。
- 初始化时将超过恢复阈值的 `processing` 标记为 `stale` 或恢复为可领取状态。

默认单 worker 已经避免同进程内并发；数据库领取仍用于防止异常状态和未来调度器扩展。

### 暂停语义

- 暂停在领取下一个分集前生效。
- 当前正在执行的 FFprobe 允许完成，并写入成功或失败状态。
- 关闭空闲补齐只停止低优先级范围扫描，不中断新增、详情、播放、手动或计划任务。
- 手动任务暂停时保存任务状态，重启后仍保持暂停，不自动继续高强度运行。

## 文件变化和元数据版本

当前元数据解析版本定义为常量，例如 `CurrentVideoMetadataVersion=1`。

普通资源编辑采用分集 ID 增量同步，不再删除全部分集后重建：

- ID 和路径都未变化时只更新排序，保留时长、元数据和视频指纹。
- ID 未变化但路径变化时保留分集 ID 和上一次采集值，将元数据标记为 `stale`，并重置视频指纹。
- 没有 ID 的旧客户端请求可以按完全一致的路径复用尚未匹配的旧分集。
- 只有没有出现在提交列表中的旧分集才会连同元数据、指纹一起删除。
- 空分集列表表示明确清空当前资源的全部分集。
- 更新请求未提交 `dramaSeries` 字段时不修改分集，兼容旧客户端；明确提交 `[]` 才表示清空。
- 资源类型或文件库归属变化后，按当前资源状态校准视频指纹；非视频资源不保留视频指纹。
- 文件库批量路径替换与普通编辑共用失效语义：保留旧元数据值并标记 `stale`，同时重建指纹。
- FFprobe 单次执行设置超时，超时后记录为 `probe_timeout`，避免单 worker 永久阻塞。

需要重新采集的条件：

- 没有元数据记录。
- `metadataVersion < CurrentVideoMetadataVersion`。
- 分集路径发生变化。
- 当前文件大小与已保存值不同。
- 当前文件修改时间与已保存值不同。
- 状态为 `stale`。
- 用户明确选择强制重新采集。

文件大小和修改时间只在准备领取候选或探测前读取，不在每次普通资源列表查询中对整页文件执行
同步磁盘访问。列表触发可以把缺少元数据的记录入队；已有成功元数据的文件变化检查由详情、
播放、空闲补齐、计划任务或手动任务完成。

“补齐缺失并更新失效项”的手动任务和计划任务会先比较所选范围内成功记录的文件大小、修改时间，
再把变化或暂时无法访问的记录标记为 `stale`。空闲补齐配置的文件处理间隔只作用于低优先级空闲任务，
不会延迟详情、播放、手动任务等高优先级请求。

不使用完整文件哈希作为第一版变化判断，避免读取整个大视频。

## 历史数据迁移

数据库迁移只执行结构变更：

1. 创建视频元数据表、设置表和范围关联表。
2. 创建或确保默认设置，历史列表补齐和空闲补齐默认关闭。
3. 保留所有已有 `durationSeconds` 和探测状态。
4. 不为每条旧分集立即创建元数据记录。
5. 不在迁移事务中访问视频文件或运行 FFprobe。

旧分集状态解释：

```text
已有 durationSeconds + 没有 resourcesVideoMetadata
    = 时长可继续显示，但完整元数据尚未采集
```

统一采集成功后，在一个事务内：

1. 更新 `durationSeconds` 和兼容探测状态。
2. upsert `resourcesVideoMetadata`。
3. 设置 `metadataVersion` 为当前版本。
4. 清空失败信息和重试计数。

统一采集失败时：

- 不清空历史上已有的有效时长。
- 写入失败状态、错误分类、错误摘要和下次重试时间。
- 不把补齐失败传播为资源列表、详情或保存失败。

## 失败与重试

建议稳定错误分类：

- `file_not_found`
- `permission_denied`
- `ffprobe_unavailable`
- `probe_timeout`
- `invalid_metadata`
- `unsupported_format`
- `io_error`
- `unknown`

默认自动退避：

```text
第 1 次失败：1 小时
第 2 次失败：6 小时
第 3 次失败：24 小时
后续失败：7 天
```

计划任务和自动补齐默认不绕过 `nextRetryTime`。手动任务可选择“重试失败项”，但普通“只补齐缺失”
仍遵守冷却时间。强制重新采集需要明确提示成本。

## 手动补齐管理窗口

设置页新增“视频信息采集”功能，至少包含：

### 自动策略

- 新增或文件变化时采集。
- 打开详情或播放时采集。
- 浏览列表页时补齐。
- 空闲时补齐历史数据。
- 空闲等待时间、文件间隔和范围。

### 数据概况

按文件库展示：

- 视频分集总数。
- 完整元数据数量。
- 待补齐数量。
- 已失效数量。
- 失败数量。
- 正在处理数量。

统计从数据库聚合，不遍历磁盘。

### 手动任务

范围：

- 单个文件库。
- 多个文件库。
- 全部文件库。

模式：

- 只补齐缺失。
- 补齐缺失并更新失效项。
- 重试失败项。
- 强制重新采集全部。

控制：

- 开始。
- 暂停。
- 继续。
- 停止。
- 查看当前文件、进度和失败原因。

### 手动任务持久化

建议增加 `videoMetadataBatchTask` 和对应文件库关联表，保存：

- 任务 ID。
- `scopeMode=selected/all`。
- 执行模式。
- `running/paused/stopped/completed`。
- 总数、成功、失败、跳过和正在处理数量。
- 创建、开始、完成时间。

系统同时只允许一个手动批量补齐任务。任务不为每个候选视频创建永久子任务记录，具体完成情况
由 `resourcesVideoMetadata` 判断。重启后根据任务范围和模式重新查询尚未完成的数据。

## 计划任务

新增任务类型：

```text
videoMetadata
```

### 范围

第一版直接支持：

- 一个文件库。
- 多个文件库。
- 全部文件库。

建议为通用计划任务增加：

- `scopeMode`：`selected/all`。
- `cronJobsFilesBases`：计划任务与文件库多对多关联表。
- `configJsonData`：保存任务类型专用参数，并由对应处理器严格校验。

视频元数据计划任务参数：

```json
{
  "maxItemsPerRun": 100,
  "includeMissing": true,
  "includeStale": true,
  "includeFailed": false
}
```

`maxItemsPerRun` 默认 100，避免一个计划任务连续运行数天。下一轮继续查询剩余候选。

### 旧计划任务兼容

现有 `cronJobs.filesBases_id` 暂时保留：

1. 新增 `scopeMode`、关联表和任务配置字段。
2. 迁移时为已有且需要文件库的计划任务创建一条关联记录。
3. `scopeMode` 设置为 `selected`。
4. 读取旧任务时，如果关联表为空但 `filesBases_id` 非空，回退到旧字段。
5. 新建或编辑视频元数据计划任务只写新范围结构。
6. 其他计划任务逐步迁移完成前，不删除旧字段。

现有按计划任务 ID 的执行互斥继续保留，用于防止同一计划自身重入；视频元数据调度器的分集级
去重用于处理不同计划、手动任务和页面触发之间的范围重叠。

### 执行语义

```text
1. 解析 selected/all 范围。
2. 根据任务参数查询本轮候选，最多 maxItemsPerRun 条。
3. 按分集 ID 提交到统一调度器。
4. 已在队列或执行中的分集记为“已在处理中”，不算失败。
5. 等待本轮实际领取的任务完成，记录成功、失败和跳过统计。
6. 本轮没有候选时正常成功结束。
```

计划任务是用户明确创建的，不受 `idleBackfillEnabled` 影响。

资源列表接口仅根据配置提交当前页候选，不等待任务完成。详情和播放接口优先复用本次已经取得的

## 性能与资源控制

- 默认一个元数据 FFprobe worker。
- 默认每个历史任务之间间隔 1500 毫秒。
- 空闲补齐每次只查询小批量候选，默认 20 条，不把全库任务一次性放入内存。
- 手动和计划任务也分页查询候选。
- 用户正在播放、导入、刮削时暂停领取低优先级空闲任务。
- 页面接口不等待后台探测。
- 数据库写入使用短事务；FFprobe 运行期间不持有数据库事务。
- 单条成功结果在一个事务内同步更新兼容时长和元数据。

## 验收

- 老数据库升级后启动时间不会随视频数量增长，也不会立即访问 NAS。
- 已有时长升级后继续显示，探测失败不会清空已有时长。
- 新增视频默认异步保存完整元数据。
- 列表历史补齐和空闲补齐默认关闭。
- 详情或播放触发不会阻塞业务接口，也不会与后台任务重复运行 FFprobe。
- 同一分集从列表、详情、播放、手动、空闲和计划任务同时触发时最多只有一个 FFprobe。
- 低优先级任务被高优先级入口再次触发时会提升优先级。
- 手动补齐支持一个、多库和全部库，可暂停、继续并在重启后恢复。
- 空闲补齐关闭后不再领取低优先级任务，但不影响新增、详情、播放、手动和计划任务。
- 计划任务第一版支持一个、多库和全部库，并且 `all` 会包含以后新增的文件库。
- 两条范围重叠的计划任务不会重复探测同一分集。
- 计划任务每轮遵守最大处理数量，下一轮可以继续补齐。
- 文件大小、修改时间或元数据版本变化后会重新采集。
- 删除分集或文件库会清理元数据和范围关联。
- 分辨率、帧率、编码和文件大小可以在详情页正确展示。
- 可以按分辨率等级和视频编码筛选。
