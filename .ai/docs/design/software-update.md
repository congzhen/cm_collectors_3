# 静默检查与应用自更新

## 行为约定

主 Vue 前端的根组件挂载唯一更新中心，经典/现代顶部按钮均打开此窗口。重新进入主页面或移动首页后延迟 3 秒自动检查，普通路由切换不重复检查。由 `/api/update/status` 校验管理员身份（包括重载页面后保留的 cookie），不依据浏览器系统选择安装包。

浏览器同源 localStorage 保存日期、尝试次数、最近尝试时间、成功检查、已提示和免打扰截止时间。一天最多尝试 5 次（包含第一次），两次至少间隔一分钟；只在下次打开主页面时重试，不在后台连续重试。成功后当天不再自动检查，最多自动提醒一次。免打扰覆盖全部版本的完整 7×24 小时。换浏览器、访问地址或清除存储会重新计数。存储禁用时降级为当前会话。Web Locks 协调标签页；不支持时使用短期本地存储租约。

手动检查不受这些限制。自动失败无弹窗、无全局网络错误提示；主动下载或安装失败显示错误。下载在服务端执行，关闭页面不会取消；重新打开更新窗口能读取进度和待安装包。安装需再次确认，可在等待任务阶段取消。下载完成、安装完成会提示；完成后用户点击刷新页面。

## 版本和下载来源

保持现有 `updateSoftConfig.json` 的版本、更新说明和 Windows/Linux ZIP 链接格式。仅接受 GitHub HTTPS 来源，检查超时 8 秒，响应最多 2 MiB。后端缓存成功结果 15 分钟、失败 1 分钟；手动检查最短间隔 5 秒。

点击下载后根据服务端 GOOS/GOARCH 选择 amd64 包，通过 GitHub Releases API 把 `latest/download` 解析为具体 tag 的附件，确认正式 tag 与清单版本一致，读取 GitHub 的 SHA-256 digest 和大小，再下载固定版本 URL。缺失 digest、tag 不一致、预发布、不支持的平台均停止下载。暂不支持第三方镜像和独立发布签名：当前信任链是 GitHub HTTPS/API 与附件 digest；这不能替代发布账户安全措施。

GitHub digest 文档：https://docs.github.com/en/rest/releases/assets

更新器拒绝越界路径、Windows 特殊文件名/ADS、符号链接、重复/大小写冲突路径和错误平台的主程序。ZIP 最多 2 GiB、展开最多 6 GiB、最多 20000 个条目，并检查磁盘空间。支持平铺 ZIP 或共同顶层目录；包中必须有且仅有一个标准名称的服务端。Docker 内只接受无 PT_INTERP 的静态 Linux amd64 服务端。

## 安装和数据保护

更新状态、下载包、数据库备份、独立更新器和每次安装记录保存在可执行文件同目录 `.cm-updates/`。目录需要写权限。安装前进入维护状态，拒绝新的业务 API 请求和周期任务；计数已进入的请求及其后台子任务，等待扫描、转码、元数据采集、预览、指纹、头像及 AI 标签等既有工作完成。已有批次及其内部子任务允许完成；队列式转码不再领取新任务。长请求（包括播放连接）也可能延长等待，可取消安装。

停止新任务后执行 SQLite `VACUUM INTO` 一致性备份并备份工作目录的 config.yaml。备份失败停止安装。MySQL 不执行不完整的自动备份，明确要求手动备份/更新。检查目标目录权限、空间和包完整性后，复制自身为独立更新器，在原进程退出后覆盖发行包文件，保留原工作目录和参数。

保护 db、cert、日志、备份目录、config.yaml/config.json、已存在的 scraper 文件，以及配置中指定的数据、日志、SQLite、JWT 证书、自动备份路径；新增 scraper 文件可以安装。包外文件不删除。程序目录与数据保护目录重叠到主程序时拒绝自动安装。

每个被替换文件先备份至安装 attempt 目录的 original/，journal.json 记录变更。覆盖失败时逆序恢复；恢复失败保留记录并停止。更新器等待旧进程退出、覆盖文件后，按原工作目录和参数启动新版，沿用程序原有的端口占用处理逻辑，不设置更新重启专属的端口判断。新进程健康检查必须同时通过数据库就绪、版本和本次更新标识，最多等待 2 分钟。新程序已经运行后不自动回退数据库，避免迁移后使用不兼容旧结构；错误保留日志及备份供恢复。断电导致文件替换不完整时，下次启动在数据库初始化之前拒绝启动，要求按 journal/original 恢复。

支持 Windows/Linux amd64 解压直接运行。systemd 管理的实例明确要求通过服务管理器更新；旧 Docker 实例提示先升级镜像。Windows 目录权限不足时停止，不自动请求提权。不修改 Wails/Svelte 源码，但发行包中的辅助程序文件会按覆盖规则更新；若文件被其他进程占用则恢复本次覆盖并报告。

## 发布要求

1. 在 updateSoftConfig.json 填写下一正式版本号；`build.bat` 会通过 ldflags 注入后端，不能只修改前端版本。
2. 先构建主前端（build-server）再构建服务端。Linux 使用 CGO_ENABLED=0，以兼容 Alpine/Ubuntu 镜像。
3. 打包标准名称 `cm_collectors_server.exe` 或 `cm_collectors_server`；可以包含其他程序文件。不要把 `.cm-updates`、用户数据库或本地配置打入发行包。
4. 发布匹配版本的正式 GitHub tag（例如 v3.4.0），上传对应 ZIP，确认 API 中 digest 非空后再发布指向该版本的检测清单。推荐固定 `/releases/download/v3.4.0/...` 链接；兼容原 latest 链接但会拒绝版本不一致。
5. 现有用户需手动升级一次至含更新器的版本；本次代码不会自行发布发行包或修改线上清单。

其他构建入口必须同样注入 `-ldflags "-X cm_collectors_server/internal/selfupdate.Version=版本号"`。源码直接构建的默认版本为当前 3.3.0。

## Docker 一次性迁移

两个 Dockerfile 均安装镜像内不可变的 `/usr/local/bin/cm-supervisor`，它以 PID 1 管理 `/app/cm_collectors_server`。`/app` 改为持久化应用卷，数据库原有挂载仍可保留。启动器从镜像的 `/opt/cm-seed` 为首次启动提供主程序。收到容器 SIGTERM/SIGINT 后转发给应用；应用使用退出码 75 请求更新，由启动器切换文件再启动应用，无需 Docker socket。

示例（替换镜像 tag 和宿主机目录，保留原来的媒体/数据库映射）：

```sh
docker run -d --name cm_collectors_3 -p 12345:12345 \
  -v cm_collectors_app:/app \
  -v /your/existing/db:/app/db \
  -v /your/media:/media \
  congzhen/cm_collectors_3:<支持更新器的新镜像tag>
```

使用命名卷以便删除重建容器时仍复用应用版本；不要删除应用卷。若旧容器 config.yaml 没有持久化，应先备份并迁移，确保数据路径和端口等设置不变。绑定整个空 /app 目录时，主程序会自动初始化；full 镜像的默认 scraper 文件仅由镜像预置卷内容提供，空 bind mount 需额外迁移 scraper 目录。

业务程序及内嵌前端可在容器内更新；Chrome、FFmpeg、系统依赖和启动器升级仍需新镜像。更换基础镜像时持久化卷里的应用版本继续保留。`.cm-updates` 保留备份和日志，不自动清理；确认新版本稳定后可以离线清理旧 job 目录，勿清理正在使用的任务。
