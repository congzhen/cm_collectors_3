# 使用手册更新入口

1. 先读 `README.md`、`progress.json`、`feature-map.json` 和 `manual.json`。章节 JSON 是正文唯一来源，不要重新生成或覆盖已编辑正文。
2. 严禁读取、复制或复用主开发环境、`build/`、服务端原数据库和现有媒体。只使用应用源码与 `.local/runtime/` 内本手册生成的数据；不要启动或连接 12345 上的现有服务。
3. 演示服务只绑定 `127.0.0.1:18345`，前端只绑定 `127.0.0.1:18346`。端口冲突应退出，不得结束其它进程。运行目录必须为 `.local/runtime/`；服务只嵌入 `demo/server/html` 的空白页面，前端直接运行 Vue 源码。
4. 保留并复用 `.local/runtime/demo-state.json`、数据库、原创素材与演示操作状态。已有演示库不应因为更新手册而清空。需要新数据时由脚本生成，列表页默认至少准备一屏数据；筛选结果、空状态教学及外部依赖的未验证状态如实呈现。
5. 先运行 `scripts/check_sources.py` 找出来源变化，再审阅对应功能。检查结果只代表源码指纹变化，不是功能已验证。不要仅重建 PDF 就把新增功能标为完成。
6. 新功能以固定 `id` 插入对应 `chapters/*.json` 的 `pages` 数组，保持旧 ID。优先按章节定位，不使用固定页码。新增截图保存 JPEG；复用原始截图，裁切信息放在章节 `crop` 中。
7. 外部 AI、刮削站点、电视、GPU、Wails 原生能力必须区分源码核对与实际验证。不得用假接口返回值、拼接假 UI 或预置成功状态替代真实验证。
8. 更新正文、截图、来源与验证记录后构建 PDF，生成页图检查。构建会校验文件、稳定 ID、中文文本、页数和内容下边界；人工仍需检查排版和截图内容。
9. 用户已要求图片不进入 Git，但最终 PDF 可以提交。`assets/screenshots/` 全部截图保留本机并保持 Git 忽略；摄影原图、数据库、媒体、工具、缓存与渲染图放 `.local/` 并忽略。提交正文、脚本、来源清单、维护记录和项目根目录的最终 PDF。不要强制添加图片；在其它机器重建前需恢复本机素材副本或重新生成素材并截图。
10. 完成时更新 `progress.json`、`CHANGELOG.md` 与功能映射，记录已完成、未验证依赖、下一步位置。不要修改无关业务代码或现有用户配置，不自动提交 Git。
11. 本 PDF 面向软件用户。制作过程、内部验证记录和维护方法留在项目文档中；`manual.json` 的 `internal_chapters` 不进入 PDF、目录或书签，不得因重新构建而恢复到用户手册。
12. 功能稳定 ID 只用于源工程和映射，PDF 使用中文章名、章内位置与数字图号。共用操作集中说明，避免每种显示模式重复整段切换步骤；保留各模式与标签重点配图。新增外部依赖说明应写清使用条件，内部是否已实测记录在验证文件中。
13. 用户已确认当前 Docker 只发布一种镜像。仓库仍有旧 minimal / full Dockerfile 和开发说明，不得据此恢复用户手册中的两种镜像分类。
